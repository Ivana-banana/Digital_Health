### Далее в тот же день: стабилизация 3/3 recall (`4fb380b`)

Диагностика: LLM для абстракта COMBI-v (PMID 25399551) возвращала `variance_source='unavailable'`
даже когда HR 0.69 (0.53-0.89) явно был. Причина: LLM путалась в OS/PFS + модель называла
comparator арм не как «BRAF-моно», а как «vemurafenib».

**Правки:**
- `EXTRACT_SYS` v3: few-shot с примером из multi-outcome абстракта (брать OS-HR, не PFS-HR);
  явные синонимы «hazard ratio for death» = OS-HR.
- `_primary_os_score` v2: OS-HR **с CI в проксимити** (≤ 300 символов от «overall survival» /
  «for death») доминирует над просто HR+CI (тот мог быть биомаркер / PFS); тай-брейкер
  инвертирован — берём раннюю публикацию (interim OS и есть та, что в Cochrane).
- `_merge_two` в `identity.py` — прокинул `nct_id` / `trial_acronym` (регресс: identity-дедуп
  их **терял**, отчего live-пайплайн видел `nct=None` у всех кандидатов; +1 регресс-тест).
- **QueryTerms → SCREEN_SYS (drug-class matching)**: `plan_queries` сохраняет `QueryTerms`
  из query-expansion в `state["query_terms"]`; `screen()` передаёт drug-names в prompt LLM-
  скринера. SCREEN_SYS дополнен правилом: «если target class = 'BRAF inhibitor monotherapy'
  и drug list включает 'vemurafenib', arm с vemurafenib — целевой сравнитель». Снимает
  стохастику `vemurafenib ≠ BRAF-моно`.

**Результат**: **три прогона подряд идентично 3/3**, HR 0.70 (0.69–0.71), k=5.

### Сессия 02.07: универсальные фиксы + генерализация (`18dfd92`, `7ea9b21`)

**Cached AsyncOpenAI-клиент** (`18dfd92`)
- Проблема: каждый LLM-вызов создавал СВЕЖИЙ `AsyncOpenAI`. Под burst screening
  (сотни вызовов) → сотни TCP-handshake'ов подряд → AI Studio rate-limit на connect →
  **persistent** `openai.APITimeoutError` (не транзиент). Проявлялось на большом live-корпусе.
- Fix: lazy-cached клиент, `timeout=120s`, `max_retries=2`. Держит соединения тёплыми.

**SCREEN_SYS relax** (`18dfd92`)
- Проблема: скринер требовал «reports the target OUTCOME» в абстракте. HERA/NSABP 2005 г.
  публикации сообщают DFS interim, а OS-обновления вышли позже — все резались как
  `wrong_outcome`.
- Fix: не резать по `wrong_outcome`, когда target outcome не в абстракте, но I/C/P/дизайн-РКИ
  соответствуют target PICO. Precision сохраняется в extract через `unavailable`.

**Параметризация бенча** (`18dfd92`)

### GRADE калибровка по Cochrane (`84dc60c`, `1ec5a19`)

- **Inconsistency**: I² > 90% → −2 (considerable heterogeneity), было только −1 при > 50%.
- **Imprecision**: для ratio-мер CI пересекает 1.0 (line of no-effect) → −1 (главный
  клинически значимый признак); иначе очень широкий CI (upper/lower > 4) → −1. Раньше был
  грубый порог `ci_high/ci_low > 3` без учёта пересечения нуля-эффекта.
- **Large-effect upgrade** для наблюдательных: HR/OR/RR < 0.5 или > 2.0 → +1; < 0.2 или
  > 5.0 → +2. Раньше upgrades не поддерживались.
- Backward-compat: `effect_type` / `pooled_point` необязательные.

**Пример**: frozen-eval offline demo (HR 0.61, CI 0.36–1.02, abstract-only) — теперь `low`
(было `moderate`), потому что CI пересекает 1.0.

**Live case 1**: GRADE = `moderate` vs Cochrane = `high`. Логика: `high − 1 (abstract_only)`.
Cochrane имеет full-text доступ, они не понижают. **Наша система честно оценивает свои
ограничения** — плюс для крит. 7 (снижение рисков LLM).
