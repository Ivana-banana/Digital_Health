# Обучение моделей в Yandex Cloud DataSphere — пошаговая инструкция

Инструкция для того, кто **ни разу не работал** с Yandex Cloud. Цель — обучить наши модели
(A — классификатор дизайна, C — скрининг include/exclude) в облаке, получить чекпойнты
`.joblib` и подключить их в наш пайплайн. Требование хакатона (plan §7, крит. 9): «обучено
в YC». Засчитывается любой обученный компонент за портом.

> **Важно про GPU.** Наши модели A и C — это **лёгкая LR-голова** поверх замороженных
> эмбеддингов e5-small. **GPU не нужен** — хватает CPU-конфигурации DataSphere (обучение
> занимает минуты). GPU-квоту (открытый вопрос plan §14) заказывать НЕ нужно.

---

## Что вообще происходит (модель в двух словах)

Оба ноутбука работают одинаково:

1. Берут тексты (абстракты / пары «PICO + абстракт»).
2. Прогоняют через **готовый** энкодер `intfloat/multilingual-e5-small` (скачивается с
   HuggingFace автоматически, обучать его не надо) → получают числовые векторы.
3. Обучают поверх векторов **логистическую регрессию** (`scikit-learn`) — это и есть
   «обучение».
4. Сохраняют регрессию в файл `*.joblib` (несколько КБ).

Этот `.joblib` — и есть чекпойнт. Мы кладём его в `data/models/`, и наш адаптер при live-прогоне
его подхватывает.

| Ноутбук | Модель | Выходной файл | Куда положить локально |
|---|---|---|---|
| `training/design_clf_min.ipynb` | A — дизайн исследования | `design_clf.joblib` | `data/models/design_clf.joblib` |
| `training/screening_clf.ipynb` | C — скрининг include/exclude | `screening_clf.joblib` | `data/models/screening_clf.joblib` |
| `training/reranker_ft.ipynb` | B — реранкер | *(чекпойнт не обязателен)* | — грузится с HF напрямую |

> Модель B (реранкер) чекпойнт **не требует** — адаптер `src/adapters/rerank/bge_reranker.py`
> грузит `BAAI/bge-reranker-v2-m3` прямо с HuggingFace. Ноутбук `reranker_ft.ipynb` нужен только
> чтобы **показать метрику nDCG@10** (для отчёта, крит. 9). Обучать его в YC не обязательно;
> достаточно прогнать Run All и записать число nDCG@10.

## Шаг 1. Открыть DataSphere и создать сообщество (community)

DataSphere организован так: **Community (сообщество)** → внутри неё **Project (проект)** →
внутри проекта **JupyterLab** с ноутбуками.

1. Зайди в консоль: https://console.yandex.cloud/
2. В верхнем поиске (или в левом меню сервисов) набери **DataSphere** → открой сервис.
3. Слева выбери **Communities**.
   - **Если в списке уже есть community — используй её**, новую создавать не нужно (community
     это просто «папка с биллингом» для проектов; в какой из них лежит проект — неважно).
     Переходи к Шагу 2.
   - Если списка нет — кнопка **Create community**:
     - **Name:** `ai-v-massy` (любое).
     - **Billing account:** выбери свой платёжный аккаунт (обязательно, иначе проект не
       запустит вычисления).
     - **Organization:** твоя организация (обычно одна, выбрана по умолчанию).
     - Нажми **Create**.

> **Ошибка «Community limit exceeded»** при создании — это исчерпанная квота на число
> communities (по умолчанию маленькая). Ничего страшного: **не создавай новую, а открой уже
> существующую** и клади проект в неё (Шаг 2). Если старая community не нужна — открой её →
> настройки → **Delete** (проверь, что внутри нет нужных проектов), это освободит лимит.
> Поднять сам лимит можно через раздел **Quotas** облака (DataSphere → запросить увеличение),
> но для обучения это лишнее.

> Если видишь предупреждение «no billing account» — привяжи платёжный аккаунт в разделе
> **Billing** консоли, потом вернись. Без billing DataSphere не даст запускать код.

**computing configuration**. Выбери самую дешёвую **CPU**-конфигурацию (например `c1.4`
или аналогичную «2 vCPU / 8 GB»). **GPU не выбирай** — не нужен и дороже.

## Шаг 4. Обучить модель A (дизайн исследования)

1. Открой `design_clf_min.ipynb` двойным кликом.
2. **Первая ячейка с `%pip install`** — раскомментируй строку (убери `#`), чтобы стало:
   ```python
   %pip install -q sentence-transformers scikit-learn joblib
   ```
   Это ставит зависимости в облачное окружение проекта.
3. В меню сверху: **Run → Run All Cells**.
4. Что произойдёт по ячейкам:
   - установятся пакеты (первый раз ~1–2 мин);
   - скачается энкодер e5-small с HuggingFace (~1 мин);
   - обучится LR, распечатается `classification_report` (метрики per-class);
   - последняя ячейка сохранит `design_clf.joblib` в файловом браузере проекта.
5. Убедись, что в файловом браузере слева появился **`design_clf.joblib`**.

> **Про данные (крит. 9).** Сейчас в ячейке `data = [...]` — **крошечный демо-сэмпл** (8
> примеров). Этого достаточно, чтобы получить рабочий чекпойнт и формально закрыть «обучено в
> YC». Но для честной метрики жюри лучше заменить `data` на **50–100 размеченных вручную**
> абстрактов (значения меток строго: `rct`, `observational`, `review`, `case_report`). Тогда
> `train_test_split` даст осмысленный per-class F1 (цель 0.7–0.8) на hold-out. Разметку можно
> собрать из абстрактов PubMed по нашим gold-кейсам. Это опционально и не блокирует питч.

## Шаг 5. Обучить модель C (скрининг include/exclude)

1. Открой `screening_clf.ipynb`.
2. Раскомментируй `%pip install` (если пакеты уже стоят с шага 4 — можно не трогать, но
   безопаснее оставить).
3. **Run → Run All Cells.**
4. Ячейки:
   - строят пары `PICO [SEP] title. abstract`, кодируют e5-small;
   - обучают LR, печатают **`recall(include)`** и `classification_report`;
   - сохраняют `screening_clf.joblib`.
5. Проверь: `recall(include)` должен быть **≥ 0.95** (модель работает как recall-first второе
   мнение — «не терять РКИ»). Порог `threshold = 0.3` в ячейке совпадает с адаптером
   (`src/adapters/screen/biencoder_clf.py`) — **не меняй** его, иначе поведение разойдётся с
   пайплайном.
6. Убедись, что появился **`screening_clf.joblib`**.

> Здесь тоже стоит демо-сэмпл (4 пары). Для честной метрики — заменить `rows` на реальную
> разметку include/exclude. Метки строго: `include` / `exclude`.

## Шаг 9. Обязательный live-регресс (после подключения моделей)

Модели A и C **меняют отбор и разметку дизайна**, поэтому после подключения нужно убедиться,
что наши воспроизведения Cochrane не сломались:

```bash
make eval-live-all
```

Ожидаем прежние **3/3 PASS** (BRAF+MEK, anti-PD-(L)1, sotorasib-отказ). Если какой-то кейс
просел по recall или точке HR — значит модель C режет нужное РКИ или модель A мислейблит
дизайн; тогда возвращаемся к порогу/данным. Этот прогон + записанные метрики (per-class F1
модели A, recall модели C, nDCG@10 реранкера) закрывают критерий 9 «обучено в YC + метрики».

# План Б: обучение на Compute VM (если DataSphere недоступен)

Если DataSphere заблокирован квотой (`Community limit exceeded` в организации `cloud-academy`),
модели можно обучить на обычной **виртуальной машине** в том же Yandex Cloud. Это по-прежнему
«обучено в YC» — критерий 9 закрыт, community не нужна.

**Идея простая:** поднимаем одноразовую Linux-VM → загружаем на неё маленький скрипт обучения →
запускаем → скачиваем готовые `.joblib` → удаляем VM. Всё занимает ~15 минут и стоит копейки.

> **Почему не нашу `ai-v-massy-vm`?** Та VM — контейнерная (крутит Streamlit-образ), заходить
> в неё и ставить Python неудобно. Проще поднять чистую **одноразовую** Ubuntu-VM только под
> обучение и потом удалить.

> **Что нужно заранее:** `yc` CLI уже настроен (ты пользовалась им на деплое, фолдер `default`
> `b1g1itmj63behhdelake`). Проверить: `yc config list` — должны быть `token`, `cloud-id`,
> `folder-id`. Всё остальное командами ниже.

---

## Шаг 1. SSH-ключ (один раз)

На Windows в PowerShell/Git Bash:
```bash
ls ~/.ssh/id_ed25519.pub    # если файл есть — ключ уже готов, переходи к шагу 2
ssh-keygen -t ed25519       # если нет — создать (Enter на все вопросы, без пароля можно)
```
Публичный ключ (`~/.ssh/id_ed25519.pub`) отдадим VM при создании, чтобы заходить по SSH.

## Шаг 2. Поднять одноразовую Ubuntu-VM

```bash
yc compute instance create \
  --name train-vm \
  --zone ru-central1-a \
  --cores 2 --memory 4 --core-fraction 100 \
  --create-boot-disk image-folder-id=standard-images,image-family=ubuntu-2204-lts,size=20 \
  --network-interface subnet-name=ai-v-massy-subnet,nat-ip-version=ipv4 \
  --ssh-key ~/.ssh/id_ed25519.pub
```
- **4 ГБ RAM** — важно: под torch + e5-small 2 ГБ впритык, 4 надёжно.
- `nat-ip-version=ipv4` — даёт публичный IP, чтобы зайти по SSH.
- Подсеть `ai-v-massy-subnet` — та же, что у нашей UI-VM (уже существует).

Узнать публичный IP:
```bash
yc compute instance get train-vm --format json \
  | python -c "import sys,json; print(json.load(sys.stdin)['network_interfaces'][0]['primary_v4_address']['one_to_one_nat']['address'])"
```

## Шаг 3. Зайти на VM и поставить зависимости

```bash
ssh yc-user@<IP>          # если yc-user не пускает — попробуй ubuntu@<IP>
```
На самой VM:
```bash
sudo apt update && sudo apt install -y python3-pip
pip3 install --break-system-packages sentence-transformers scikit-learn joblib
```
(первый `pip` тянет torch — пара минут).

## Шаг 4. Загрузить скрипт обучения на VM

Скрипт `training/train_models.py` — **самодостаточный** (не зависит от нашего репо: только
sentence-transformers + sklearn + joblib). *Его я генерирую отдельно — см. заметку внизу.*

С локальной машины (из корня проекта, новый терминал):
```bash
scp training/train_models.py yc-user@<IP>:~/
# если готовишь свои размеченные данные — заодно:
# scp data/raw/design_labels.csv data/raw/screening_labels.csv yc-user@<IP>:~/
```

## Шаг 5. Запустить обучение

На VM:
```bash
python3 train_models.py
```
Скрипт: кодирует тексты e5-small → обучает LR → печатает метрики (per-class F1 модели A,
`recall(include)` модели C) → сохраняет `design_clf.joblib` и `screening_clf.joblib` рядом.

## Шаг 6. Скачать чекпойнты в проект

С локальной машины:
```bash
scp yc-user@<IP>:~/design_clf.joblib    data/models/
scp yc-user@<IP>:~/screening_clf.joblib data/models/
```
(создай папку `data/models/`, если её нет).

## Шаг 7. Удалить VM (чтобы не капало за простой)

```bash
yc compute instance delete train-vm
```
(или `yc compute instance stop train-vm`, если думаешь ещё дообучать позже).
